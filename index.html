Cracking a Password One Character at a Time

This simulates the vulnerable password checker from Learning Sprint 3. Instead of just saying "right" or "wrong," the program leaks how many characters are wrong in your guess. That single extra number is a side channel: it lets you solve the password one position at a time instead of guessing the whole thing at once.

Why this matters: A secure comparison should only ever tell you match or no match. This program instead tells you how close you are, which is exactly the kind of leak we covered with length checks and mismatch counts. The automatic attack button runs the same character by character strategy from Problem 2, locking in one correct character at a time instead of brute forcing the whole password.

How Fast Does the Work Grow?

Drag the slider to change the input size and watch how the amount of work grows for three different kinds of code: a normal O(n) loop, an O(n squared) nested loop like a naive regex engine doing extra backtracking, and an exponential blowup like catastrophic backtracking or the Rectangle linked list cycle bug from Problem 4. The y axis is log scale so the exponential line does not fly off the screen immediately.

Why this matters: This is the same pattern behind a ReDoS regex (Problem 3) and the shapes catalog bug (Problem 4). The input barely grows, but the amount of work the program has to do rockets upward. That mismatch is exactly what an attacker exploits: a small, normal looking input that quietly makes the program do a huge amount of work or crash.
